# ADR-0012: 重建为 Lima Design System——独立项目,契约数据为自有源

- 状态:已采纳(2026-11-16)
- 关联:取代 ADR-0001~0011 所描述的实现(其决策记录保留为历史);ADR-0013(意图分级)

## 背景

此前的实现(LLP)以占位 token、五个自研 CSS 组件和一个以 token 查询为主的 MCP 跑通了管线,
但离"enterprise 设计系统被 agent 消费"的真实形态有三处距离:

1. 组件是 CSS 片段而非 React 组件库,agent 面对的不是真实的 props / 组合 / 版本问题
2. 数据没有按"传达了多少设计意图"分层,无法回答"哪些信息在控制生成漂移"
3. 没有评测,MCP 的效果只能凭感觉

目标变为:以一套完整的 enterprise 级设计系统契约,跑通并度量 agentic 消费。

## 决策

1. **整体重建,旧实现归档**。旧状态保留在分支 `archive/llp-spectrum-v0`;重建在集成分支
   `lima` 上进行,每一步一个 PR;全部就绪后一次性切换到 `main`。期间 `main` 上的旧 MCP 照常可用。
2. **Lima 是独立项目,契约是自有的编写源**。`packages/contract/tokens/` 与 `components/` 下的
   JSON 文件就是事实源:没有上游、没有摄入步骤、没有生成物。改设计决策 = 改这些文件并提 PR。
3. **范围**:web / React;token 两个模式(light、dark),只保留通用的 base 与 functional 两层
   (组件内部 token 不属于对外契约);组件十个(选择理由见 ADR-0013)。
4. **命名**:
   - 设计系统名 Lima Design System
   - CSS 自定义属性一律 `--lima-` 前缀,其后是 token 名;token 名 = 路径用 `-` 连接
   - 组件从 `@lima-design/react` 导入;实验性的在 `/experimental`,已废弃的在 `/deprecated`
   - 包 `@lima-design/*` 先保持 private,不发 npm
5. **契约先于实现**。本阶段只有契约数据;`@lima-design/react` 的可运行实现在消费端样例那一步
   再引入。契约是实现必须满足的规格,而不是从实现里抽出来的文档。

## 关于样例数据

Lima 的初始值与组件签名不是从零设计的:为了尽快有一套内部自洽、规模真实的数据来验证
agentic 消费,初始内容借用了一套成熟开源设计系统的设计决策(许可与出处见仓库根目录的
`THIRD_PARTY_NOTICES.md`)。借用的是决策本身;Lima 与其没有依赖关系,数据自此由 Lima 维护,
可以自由演进。

## 备选方案

- 在旧实现上增量改造——旧的三层 token 结构与 CSS 组件注册表和新目标的数据形状不兼容,
  改造成本高于重建
- 保留一个"上游 + 摄入适配器"的管线——适合真的要长期跟随某个供应商设计系统的团队;
  Lima 的定位是独立系统,引入上游只会让每个决策都多一层"这是谁的决定"的歧义

## 后果

- 没有构建步骤,也就没有"生成物与源不一致"这类问题;校验只需面向一份源文件
- 契约文件一行一个 token:一次设计变更的 diff 就是被改动的那几行
- 契约文件目前是自定义 JSON,值为 CSS 形态(`#59636e`、`0.5rem`)。迁移到 DTCG 2025.10
  编写格式(颜色与尺寸为对象形态,模式用 resolver 表达)列为后续:它的收益主要在与设计工具
  互通,而那是更靠后的一步;在此之前 MCP 与门禁消费的都是 CSS 形态的值
- 契约先于实现,意味着在实现出现之前,类型检查类的门禁无物可查;这是 Step 4 的前置条件
